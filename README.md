# 照片变画册

把一个照片文件夹做成一本书：有封面、扉页、跨页排版的照片、版权页、封底，能像真书一样翻页。

**只有一个入口：**

| 入口 | 双击它会怎样 |
|---|---|
| **双击 `画册.bat`** | 打开网页工作台：左边照片、中间跨页预览、右边书名与版面。可以拖拽换顺序、逐张改大小、实时看效果，满意再点「生成画册」 |

只想快点出书也行 —— 工作台右下角就是「生成画册」，一条路走到头。

**想关掉后台服务**：点页面右上角的「关闭工具」。直接关掉浏览器窗口也等于关掉它。

> 已经开着一个工作台时再双击 `画册.bat`，**不会**再起第二个服务 ——
> 它会认出原来那个，直接把它的页面再打开一次。

不需要联网，不装任何东西，照片不会离开这台电脑。

> **双击后没反应？** 先看 `logs\工作台启动位置.txt`，里面写着界面地址和启动时间。
> 界面没弹出来，就把那个地址复制到浏览器打开。

> **想知道它一路改了什么？** 更新记录在 **[`CHANGELOG.md`](CHANGELOG.md)** ——
> 每个版本一段，只记留下来的、算数的变更（改错又改回去的不占篇幅，那些留在 git 提交历史里）。

## 用工作台调版式（推荐）

1. 双击 `画册.bat`，浏览器自动打开工作台
   （这个入口故意不留黑窗口：它用 `pythonw.exe` 在后台起服务，一闪即退是正常的）
2. 点左下「选择照片文件夹…」选装照片的目录
3. 中间就是画册翻开的真实样子。想改：
   - **换顺序**：直接拖左边的照片卡片
   - **删掉某一张**：把鼠标移到那张照片上，**图片的右上角会浮出一个圆圈叉号**，点它就删掉这一张
     （只剩一张时删不动——会告诉你「至少要留一张」）
   - **按号挪位置**：每张照片**左下角有个数字**，点一下这个数字它会**就地变成输入框**，
     填个「第几位」、按回车（或点别处）就挪过去，其余照片自动让位。
     比如把第 3 张填成 `10`，它就插到原来第 9 张后面、变成第 10 张，中间的依次往前挪一位。
     填了 0、超出总数、或者填写的不是数字，就**当没听见**，原地不动，也不弹错。
   - **改某张的大小**：点一下那张卡片，右边「版面」面板选 小/中/大/竖
   - **微调位置**：同一面板选 居中/上/下/偏右
   - **改书名**：右边「书名」输入框，改完预览立刻跟着变

   > （左下角那个数字 = **它现在排第几**。不管是删照片、拖顺序，还是填数字挪位，
   > 它都会**立刻重排成 1、2、3…**，跟眼睛看到的顺序永远一致。
   > 照片自己另有一个"身份证号"在后台认图，那个不显示、也不会受这些操作影响。）

4. 想看得更大？点右边按钮区**最底下那个「全屏看预览」**（就是工具自己的右下角）——
   整个电脑屏幕上就只剩中间的画册预览，顶栏和左右两栏都让开。
   右下角有个**很淡的叉号**用来退出；**三秒不动它会自己隐起来**，
   但那个位置照样点得动（不用先把它叫出来）。
5. 满意后点「生成画册」，完成后会多出「打开画册」「打开所在文件夹」两个按钮
6. 还想调封面上的字？点右边那个**「编辑封面文案」**按钮，会弹出一个编辑窗口：
   - 窗口左边是**封面的真实样子**（后台用同一份生成器、同一套样式渲染的，不是画个像的示意图
     —— 免得出现「预览好看、出书难看」）
   - **直接用鼠标拖**封面上的文字框，位置就跟着走（松手才生效，拖动过程中不会来回闪）
   - 右边一排页签：**书名 / 副标题 / 页脚** 三个是原本就有的，调各调的
     字号、颜色、字体（衬线/无衬线/黑体/宋体/楷体）、对齐（居左/居中/居右）、斜体、距顶/距边
   - **想用自己的字体**：「字体」下拉的最后一项是「＋ 从电脑里选字体…」，
     选一个 `.ttf / .otf / .woff / .woff2` 文件就行。它会**收进工具自带的字体库**
     （`user-fonts\`），以后每本书的字体下拉里都能直接选它；出书时会**跟着书一起走**，
     所以拷给朋友的那份画册也是这个字体。详见文末「封面引入外部字体」
   - **想多写几行字，就点「＋ 加文字框」** —— 会多出一个新页签，它就是个空白文字框，
     同样能打字、能拖位置、能调字号颜色字体对齐。不想要了，选中它点**「删掉这个框」**即可
     （自定义框最多同时留 8 个。内置的书名/副标题/页脚也能「删」——那是**先藏起来**，
     页签会留着并划掉，方便你找回来；这时候那个按钮自己会变成「恢复显示」，点一下又露出来）
   - **选中一个框，它右下角会冒出一个小方块** —— 按住那个小方块拖，框会**连字一起等比放大缩小**。
     想改大小、又不想动正文里的字号设置时，用它最省事
   - 「这块恢复默认」只清当前页签那一项；「全部恢复默认」所有项一起清回出厂
   - 调完点**「确定」** —— 关闭窗口、回到工作台主界面；点「取消」或按 `Esc` 则**整段撤销**，
     回到你打开窗口之前的样子

排版方案的唯一事实来源在后台服务里：每次改动浏览器都会提交回去，由服务端重算书页结构再返回。所以预览显示的就是成品的样子。

改完不用记得保存，关掉页面即可。想换一批照片，再点一次「选择照片文件夹…」。

## 翻画册时的几件小事（底部控制条 + 屏幕右下角）

> 底部的控制条是**两行**：第一行是"页数"（状态 + 跳到第 N 页），第二行是"自动翻页"
> （开关 + 速度），两边的 ← → 属于两行。整条实测 **49.6px 高**（以前竖排五行是 121.2px），
> 所以书能占满画面的绝大部分（实测书占视口 **71%~80%**）。
> 以前底部还有一行"点击页码可跳转 · 拖动或方向键翻页"的小字说明，**已经删掉了**（Phase 31）。

- **跳到某一页** —— 第一行有**两个口子，随便用哪个**：
  - 那个**常驻的「跳到第 ___ 页 [跳转]」**：直接输页码、点跳转或按回车就跳过去（一眼就能看出这里能跳页）
  - 它左边那个**页码本身**：点一下它会变成一个输入框（预填当前页，已全选），输数字回车也能跳
  两个口子吃同一套规矩：`0` / 超大数会被夹到第一页 / 最后一页，乱输不跳、退回当前页，不会报错；`Esc` 取消。
- **自动翻页** —— 第二行「自动翻页」按钮，点一下开始、再点一下停（默认是关的）。
  你只要碰一下键盘方向键、两侧箭头、拖一下书页、或点页码跳页，它就让位停下。
  翻到最后一页会自己停；在末页再点「开始」，会从封面重新播一遍。
- **调速** —— 「自动翻页」**右边**那个下拉框，**1 秒 ~ 10 秒一页，一共 10 档**，每档差 1 秒
  （最快的 1 秒档是后来加的，想快速过一遍时用它）。
  默认 5 秒（也就是原来的快慢）。播放中改档**立刻生效**，不用停下重开。
- **翻到最后能合上，也能整本翻回封面** —— 走到最后那一跨页（版权页 + 封底）之后再点一下「→」，
  封底会**翻过来把画册合上**：画面上只剩封底那面，居中摆着，状态条写 `Back cover`。
  **再点一下「→」**，整本书会被翻过来、回到封面，状态条回到 `Cover`，可以重新看一遍
  （从末跨页算起正好两下：① 合上 ② 翻回封面）。想倒着来就点「←」，书会原样翻开。

- **全屏看** —— 控制条**第二行最右边那颗「全屏」**（和「自动翻页」「5 秒」并排）。
  点一下，浏览器进入**真正的全屏**：**标签页、地址栏，连系统任务栏一起收走**，整块屏幕只剩画册。
  > ★ 不过多半用不着它了：从工作台点「打开画册」进来的画册，**打开时就已经是
  > 无边框全屏**（没有标签页、没有地址栏，屏幕最上方就是画册本身）——
  > 那种模式下退全屏按 **`F11`**，见下面「Phase 40」那一节。
  全屏里控制条**默认是收着的**（照片铺满整屏），**动一下鼠标它就浮出来**、闲下来自己再收回去；
  翻页 / 跳页 / 自动翻页在那条上照常能用。
  这时候那颗「全屏」会**自己搬到屏幕右下角**，**正好压在「收起条 / 显示条」那颗的上面** ——
  两颗排成一竖列，相对位置永远不变；它自己写成 **「退出全屏」**，
  再点一下、或者按 `Esc` / `F11`，都能退出来。
  > 为了不抢照片，全屏里**这两颗都是淡的**（不透明度 0.3）—— 不仔细看几乎发现不了。
  > **鼠标压上去（或按 Tab 选中）立刻亮回原样**，想用的时候它自己就出来；
  > 淡化只是"颜色变淡"、**不是"关掉"，照样点得着**。
  > 按 `F11`（或从工作台点「打开画册」）进去的那种全屏**不搬**，那颗仍留在控制条第二行 ——
  > 那种全屏浏览器不允许网页自己退出去，搬出来只会多一颗点了没反应的按钮。
  这两颗按钮都是**画册自己带的** —— 把整本书的文件夹拷给朋友，他那台电脑上一样有。

- **把控制条收起来（右下角那颗小药丸）** —— 屏幕右下角**常驻**一颗很小的开关：
  控制条开着时它写 **「收起条」**，点一下整条收走、画面顶满；
  收走后它自己写成 **「显示条」**，再点一下控制条就回到照片下方。
  > 在全屏里按它 = 把控制条叫出来 / 收回去；在普通窗口里按它 = 操作条整条收起、画面顶满。
  > 这颗开关**自己永远不藏** —— 藏了就再也叫不回来了。

- **放大照片看细节** —— **直接滚滚轮就行**（不用按任何键）：向上放大、向下缩小。
  放大后**鼠标指着照片上哪一点，那一点就不动**（实测漂移 **0.000 照片像素**）；
  一直往上滚，照片会**逐步长大到铺满整个屏幕**（滚到约第 7 格铺满，此后贴着屏幕边继续放大），
  **4 倍封顶**。一翻页就自动回到原样。
  ⚠ **按住鼠标中键（滚轮键）不放时，什么都不做** —— 不放大、不翻页、不拖拽
  （放大的动作靠"滚"，不靠"按"）。

> **窗口拉矮了也不会挡住字** —— 书会自己缩小让开底部那排按钮。
> 实测 1440×900 到 760×620（含它们之间的各种尺寸）都不再压到「跳到第 __ 页」那行。

## 不想调，直接出书

1. 双击 `画册.bat` 打开工作台
2. 点左下「选择照片文件夹…」选**装照片的那个文件夹**
3. 右栏填书名（可不填），点「生成画册」，等进度跑完
4. 点「打开画册」——**直接顶满整屏打开**，没有标签页也没有地址栏
   （想退全屏按 `F11`）；翻页：拖页面角、点左右箭头、按方向键都可以

> 想跳过界面也行 —— 在命令行里直接出书（见下面「想改书名」的 `--cli` 用法）。

生成结果统一放进工作区的 `画册集\` 目录里，一本书一个文件夹（文件夹名 = 书名）。
每做一本，`画册集\画册目录.md` 会自动更新一版，列清哪本是哪本、几张照片、什么时候做的。

想换位置见下面「改输出目录」。

## 画册集在哪、怎么回看

```
3D画册2.0\
├── 画册集\                  ← 做好的画册都在这儿，一本一个文件夹，可反复翻看
│   ├── 画册目录.md           总目录（工具自动维护）
│   ├── 我的小狗\             书名即文件夹名
│   └── ...
├── 图片\                    ← 照片源（原图，工具只读不改）
└── photo-flipbook-tool\     ← 工具本体
```

看哪本就直接进对应文件夹双击 `index.html`。整个文件夹是离线的，拷给别人也能看。

> 这个位置只写在一个地方（`app/make_flipbook.py:default_output_dir()`），
> 出书和工作台「输出到」那一栏都取自它 —— 不会出现两处各说各话。
> 工作台里临时改过目录后，那一栏旁边会出现「默认」按钮，一键回来。

## 想改书名

默认标题是「我的小狗 / Photographs」。改名有两种方式：

**方式一：命令行带参数**（推荐，一次生效）

```bat
画册.bat --cli "C:\我的照片" -t "夏日午后" -s "2026 · 夏"
```

**方式二：改代码里的默认值**

打开 `app\make_flipbook.py`，找到这两行改掉：

```python
DEFAULT_TITLE = "我的小狗"
DEFAULT_SUBTITLE = "Photographs"
```

**方式三：在工作台里直接改**

右侧「这本书」→ 书名 / 副标题，敲进去就实时同步到左边的预览（防抖 420ms）。

> **留空会怎样**：书里仍用默认书名「我的小狗」，输入框下面会出现一行小字提醒。
> **但输入框不会自己填回去** —— 你可以把原来的字删干净，再打新的，中间不会被打断。

## 改输出目录

```bat
画册.bat --cli "C:\我的照片" -o "D:\我的画册集"
```

`-o` 指的是**画册集**（装很多本书的那个文件夹），不是某一本书的文件夹 ——
工具会在它下面自动建一个以书名为名的子文件夹，把书放进去。
不给 `-o` 就默认用工作区的 `画册集\`。
工作台里也能改：右栏「输出到」那一栏点「改」选目录，想回到默认就点旁边的「默认」。

> **想直接把书铺在某个文件夹里**（不要子文件夹）加 `--flat`：
> ```bat
> 画册.bat --cli "C:\我的照片" -o "D:\临时看看" --flat
> ```
> 一般用不着。书一旦铺开，那一层就不能再放第二本书了。

**单独维护画册目录**（一般用不着，出书时会自动更新）：

```bat
python app/make_index.py                    # 扫画册集，重写 画册目录.md
python app/make_index.py --print            # 只打印看看，不落盘
python app/make_index.py --dir "D:\我的画册"  # 指定别的画册集
```

## 改排版

照片是**整页铺满**的：等比放大到填满整页，比例不合的部分裁掉，照片之间不留白。
裁切时主体会有轻微位移，靠下面的参数控制。

自动排版会为每张照片选一个裁切中心（`high` 往上、`low` 往下、`aside` 偏右），
所以「抬头看镜头」和「低头趴着」的照片都能把主体留在画面里。如果排出来不合心意：

1. 打开生成目录里的 `排版清单.txt`，对照页码看当前安排
2. 打开 `book-plan.json`，里面每张照片的 `plate`（small/medium/large/portrait）和 `position`（high/low/aside）就是裁切参数
3. 告诉我你想怎么调，我改规则或者直接手工指定某一页

裁切中心的位置（相对页面）：

| plate | 裁切中心纵向 | 适合 |
|---|---|---|
| `small` | 54%（偏下） | 安静的远景，主体偏下 |
| `medium` | 46% | 常规 |
| `large` | 42%（偏上） | 主体在中上部的大图 |
| `portrait` | 40%（偏上） | 竖构图，主体偏上 |

`position` 再叠一层：`high` → 34%、`low` → 60%、`aside` → 横向偏右 62%，不给就用 plate 自己的值。

## 跨页之间的那条过渡

两张照片之间的装订线位置做了两件事，都是刻意压淡的：

1. **柔和的纸缝过渡（书脊渐变）**：离中线最近处有一层约 26% 的暗色，向外迅速转淡、到 86% 处完全透明。整条带子占页宽的 **20%**（512px 的页面上约 102px）。
2. **一条极细的分界线**：2px、最深 40% 的暗线，正落在两张照片中间。

远看只是两页自然接在一起，凑近才能看出那里有「两张纸叠在一起」的厚度感。
刻度的**宽度**写在 `runtime/styles.css`，**颜色**写在 `runtime/style/book-style.css` ——
分成两个文件是有原因的，见下面那节。

工作台的预览用的是同一套数值（`ui/style.css`），所以**预览看到什么，生成出来就是什么**。

## 照片外侧的那圈淡阴影

只有**没有和另一页相接**的那几条边才有阴影：

| 页面 | 有阴影的边 |
|---|---|
| 左页（verso） | 上、左、下 |
| 右页（recto） | 上、右、下 |

贴中线的那一侧**故意不给** —— 那里已经有跨页过渡带 + 2px 分界线，再叠一层就显脏了。

做法是四块只有几个像素高的黑色渐变（`outer-y` 管上下、`outer-x` 管左右，
因为一个元素画不出方向相反的两个渐变），再用 `opacity: .72` 统一压强度。
最终最深处约 **9%** —— 就是「只要一点」的量级，翻页时能感觉到照片有厚度，
但不会看见一条黑边。

这些元素由 `make_flipbook.py` 的 `outer_shadow_html()` 生成，
工作台预览里由 `ui/app.js` 的 `outerShadow()` 对应生成。

**注意：这圈阴影和契约测试无关**，契约只要求那两条 `::before` 存在、有渐变、`z-index:3`，
不检查宽度和颜色，所以这圈阴影是纯粹的自由发挥，改多改少都不会让测试红。

## ★ 翻页方向：`flipNext` / `flipPrev` 的参数是个大坑

如果你要改翻页逻辑，**先看这一节，能省你半天**。

`stPageFlip` 的翻页方法签名是：

```js
pageFlip.flipNext(corner);   // corner: "top" | "bottom"
pageFlip.flipPrev(corner);
```

**`corner` 是「从哪个角开始卷」，不是「往哪个方向翻」。**

| 传值 | 实际动画 |
|---|---|
| `"top"` | 从顶部起卷，页面**绕书脊竖直翻转** —— 就是真书翻页的样子 ✅ |
| `"bottom"` | 从**底部角**起卷，是「捏住书角斜着掀起来」的手势动画 ❌ |

之前按钮和键盘都传了 `"bottom"`，于是出现三个症状，全都在用户的描述里：

1. **歪斜** —— 整页会绕对角线做一个**斜切变换**（对 `clip-path` 多边形 + `rotate` 同时插值），
   中途页面在屏幕上是斜着躺的。
2. **盖住整张跨页** —— 斜切时那一页会同时压在左右两半上，还会明显向上/向下**探出书框**。
3. **卡顿感** —— 帧率其实是健康的（实测 0 帧 >20ms、平均 16.6ms），
   「卡」是大脑对斜切动画的观感，不是掉帧。

**结论：按钮 / 键盘这类"啪一下整页翻过去"的触发，一律用 `"top"`。**
只有想复刻"手指捏住书角掀页"的手势时，才用 `"bottom"`。

对应的代码在 `runtime/flipbook.js`，统一收在两个函数里：

```js
function turnNext() { if (!isTurning) pageFlip.flipNext("top"); }
function turnPrev() { if (!isTurning) pageFlip.flipPrev("top"); }
previousButton.addEventListener("click", turnPrev);
nextButton.addEventListener("click", turnNext);
// 方向键 / 空格 也都走这两个函数
window.__pf = pageFlip;   // 自测与调试入口
```

### 怎么防止它被改回去

`verify_book_ui.mjs` 里加了一条**翻页中途几何断言**：
点一次"下一页"，用 `requestAnimationFrame` 连续采样翻页中那一页的**投影外接矩形宽高比**，
要求所有帧都落在 `0.8 ~ 1.35` 之间（页面本身 640/512 = 1.25，透视会让它小幅摆动）。
斜切翻转会把这个比值推到 1.7 以上，立刻红。

**判据为什么用宽高比、不用 `transform` 矩阵**：`matrix()` 的 `b` / `c` 分量在**纯 `rotate()`** 时
同样是非零的，拿它判断会把正常旋转误判成错切 —— 我第一版就是这么写的，产生了假报警。
`rotateY` 在 `perspective: 2000px` 下，`getBoundingClientRect()` 返回的是**透视投影后的**外接矩形，
翻页中途高度从 648px 涨到 860px 是**正常现象**，此时 `offsetHeight` 始终精确等于 640px。
**别去"修"它。**

## ★ 拖拽翻页的「卡一下」

这是另一条独立的问题：**点一下按钮完全正常，但用手指/鼠标按住页面一直拖着翻，会短暂卡一下。**

库内部对"翻页"有**两条完全不同的代码路径**：

| 触发方式 | 走的路径 | 动画方式 |
|---|---|---|
| 点按钮 / 按方向键 | `flip()` | 固定 760ms 匀速补间，中途不看指针位置 |
| **按住拖动** | 每次 `mousemove` → `fold()`，松手 → `stopMove()` | **按当前指针位置实时算进度**，松手后从当前位置补一段到落点 |

卡顿出在第二条路径上，原因有两个，叠加在一起：

**原因一：`showPageCorners` 的悬停提示动画抢戏。**
这个选项为 `true` 时，鼠标悬停到页面角落会让页角**先自己掀起 50px** 做"这里可以翻"的提示。
拖动一开始，如果指针恰好扫过角落，就会先播这个提示动画再切到拖拽跟随 —— 肉眼看到的就是一次顿挫。
画册用按钮 + 拖拽两种方式翻页，**完全不需要这个悬停提示**，所以关掉：

```js
showPageCorners: false,   // runtime/flipbook.js
```

**原因二：拖拽期间控件状态被反复改写，和外层过渡打架。**

- 拖拽中 `state` 会在 `user_fold` → `flipping` → `read` 之间来回切，
  每次 `changeState` 都去写按钮的 `disabled`，造成按钮闪烁 + 一次可见停顿。
  → 用 `isDragging` 标记把它挡住，等 `pointerup` 之后统一刷新：

```js
if (!isDragging) {
  previousButton.disabled = currentPage === 0 || isTurning;
  nextButton.disabled = currentPage === lastPage || isTurning;
}
```

- `.book` 外层挂着 `transition: translate 760ms ease`（给封面/封底挪位置用的）。
  拖拽时库每帧都在改内部元素的 transform，外层再挂一条 760ms 缓动，起步和松手各迟滞一下。
  → 拖拽期间给它打 `data-dragging`，用 CSS 把过渡关掉：

```css
.book[data-dragging] { transition: none; }
```

**顺带加的一条触屏卫生**：横向拖拽在手机上很容易被浏览器当成页面滚动/回弹抢走事件。
`touch-action` 在比 `preventDefault` 更早的阶段就把手势归属定死：

```css
.book, .book-page, .stf__block, .stf__item { touch-action: none; }
```

**实测结果**（真浏览器模拟按住拖动 965ms）：

| 指标 | 修复前 | 修复后 |
|---|---|---|
| `showPageCorners` | `true` | `false` |
| 最长帧 | 有可见顿挫 | **46ms**（中位 17ms） |
| >50ms 的长帧 | — | **0** |

回归断言已加进 `verify_book_ui.mjs`，用**真实鼠标事件序列**拖动并采样帧间隔，
既要求画面真的翻过去（否则"不卡"可能只是"没动"），也守住帧预算。

> **这条断言的判据放宽过一次（第十轮）**：原来写死「`>50ms` 的长帧必须为 0」，
> 但实测最长帧长期在 **42 / 46 / 48 / 54ms** 之间抖，50ms 这条线正好压在这台机器的
> 噪声地板上 —— 机器一忙（比如后台还开着另一个工作台）就会出现 1 帧 54ms 的假红。
> 现在改成三条一起看：**中位帧 ≤ 24ms**（主体真的在 ~60fps）、**`>50ms` 的帧 ≤ 2**（允许系统抢占造成的孤立帧）、
> **最长帧 ≤ 90ms**（不允许真正的长停顿）。
> 原始那个 bug 是**持续性**顿挫，会一口气打出好几个长帧，这三条照样拦得住。
> 顺带把 p95 也打出来，看趋势比看单个最大值可靠。

> **写这条断言踩的坑**：一开始我在页面里手工 `dispatchEvent(new PointerEvent(...))`，
> 结果是**假通过** —— 库把监听器绑在内部的 `.stf__dist` 元素上，还依赖 `clientX/clientY`
> 经过 `getMousePos()` 换算，手工构造的事件打不到它的处理链。
> **必须用 Playwright 的 `page.mouse.down/move/up`** 才能真的走通拖拽路径。

## ★ 书脊折痕阴影：为什么不能靠调 `maxShadowOpacity`

翻页时的「折痕感」来自**书脊那条暗**。这里的关键结论是：
**库自带的折痕阴影并没有落在书脊上**，所以调 `maxShadowOpacity` 解决不了这件事。

### 实测：库的阴影落在哪

把库的两层阴影分别染成不透明色再截屏，一眼就能看清（书脊在 x=700，书本正中）：

| 层 | 类名 | 实际渲染位置（相对书脊） |
|---|---|---|
| inner | `.stf__innerShadow` | x ≈ **+106 ~ +230** px |
| outer | `.stf__outerShadow` | x ≈ **+230 ~ +430** px |
| — | **书脊附近（±100px）** | **完全为 0** |

它们渲染成**两条竖直的色带，飘在跨页中右部**，距书脊 106~430px，整条书脊一点阴影都没有。
原因在库的 `setShadowData()`：

```js
opacity = (100 - i) * maxShadowOpacity / 100     // i = 翻页进度 0~100
width   = 3 * pageWidth / 4 * i / 100            // 最宽到 0.75 页宽
```

`opacity` 只是整体缩放的系数，**位置**是由库内部算的 `shadow.pos` 决定的，
跟 `maxShadowOpacity` 无关。于是把它从 `0.42` 提到 `0.88`：压暗峰值从 21.6 涨到 45.5 灰度，
但这些灰度**全加在那两条错位的带子上**。

> 实测观感：0.88 时照片上会出现**一条硬边灰条**，读起来是「照片脏了」，不是「纸折了」。
> 0.72 以上就开始明显发浑。所以 **`maxShadowOpacity` 保持 `0.42` 不动**——
> 它现在那点量算是「翻起的那页投在下面那页上的投影」，物理上说得通，加深只会更脏。

### 翻页时「到底有几层暗」—— 逐列实测

后来佘先生反馈翻页时偏暗、照片被压得看不清，于是把**两层各自的压暗足迹**逐列量了一遍
（翻页进度 50 冻结、每列取全高平均亮度，再与「只留另一层」的实拍相减）：

| 距书脊 | 书脊折痕层压暗 | 库自带阴影层压暗 |
|---|---|---|
| −108 ~ +108 px | **0 → −23.8 → 0**（峰值就在书脊上） | **≈ 0** |
| +124 px | 0 | −0.7 |
| +188 px | 0 | −2.3 |
| +252 px | 0 | −6.3（继续向外加深） |

结论：**两层落点完全不重叠**——折痕层是一条贴着书脊的窄暗带，
库那层是从书脊外侧一直铺出去的一大片投影。翻页时那种「暗」主要来自折痕层。

### 所以补了这一层：`.fold-shade`

真正缺的是「书脊本身是个凹槽，光进不去，所以最暗」这一层。做法刻意做到最轻：

```js
// runtime/flipbook.js
const FOLD_SHADE_PEAK = 0.10;        // 翻到一半时，书脊正中那一条的最终 alpha
```

* 往 `#book` 里挂一个绝对定位的 `div`，以书本正中（`left: 50%`）为轴心的对称渐变，
  宽 110px × 2 —— 与相邻两页上那条 20%（=102px）的书脊过渡带基本同宽，两者的暗部叠成**一条连续的凹槽**。
* 只在翻页期间用 `requestAnimationFrame` 改它的 `opacity`，强度走 `sin` 弧：
  翻到一半时页面弯曲最厉害 → 最深；两端归零。
* 每帧只写**一个元素的 opacity**，是纯合成器操作；`pointer-events: none` 绝不抢指针事件。
* 强度调过两次：`0.21` → **`0.10`**（见下）。深了要淡、浅了要深，只动这一个数。

**实测（成品画册，翻页进度 50）**

| 指标 | 结果 |
|---|---|
| 书脊正中压暗 | **−12.0 灰度**（0.10 时；0.21 时是 −23.8） |
| 距书脊 ±110px 以外 | **0.00**（干净收边，不外溢） |
| 静止跨页：这一层 开/关 的像素差 | **max = 0，mean = 0.0000**（静态观感一个字没变） |
| 翻页全程 opacity 弧 | `0 → 0.100 → 0 → 收尾回到 0` |
| 帧预算 | 中位 17ms，p95 39~42ms，最长 41~47ms，**>50ms 的长帧 0** |

宽度也实测对比过 132 / 176 / 220 / 264px：**220px 最像真实书脊**，
再窄就成了一条「画上去的黑杠」，再宽则淡到看不出。

回归断言已加进 `verify_book_ui.mjs`，守住三件事：静止时 `opacity` 必须**恰为 0**、
翻页峰值必须落在 `0.05 ~ 0.2`、收尾必须回到 0。
（区间特意不贴着当前值写 —— 0.10 上下留 50% / 100% 余量，见下面「断言别压在边界上」。）

> **强度为什么从 0.21 降到 0.10**
> 佘先生要求「降低一点翻页时的透明度，让照片看得清」。0.10 正好是 0.21 的一半：
> 书脊最深压暗 −23.8 → −12.0 灰度，仍然看得出书脊是个凹槽，
> 但翻页过程中照片明显更容易看清。想更淡改 `0.05`，完全不要就设 `0`。

> **排查手法备忘（下次还这么干）**
> 库的动画推进用的是 rAF 时间戳（`render(t)` 里 `this.timer = t`，
> 帧序号 = `floor((t - startedAt) / durationFrame)`）。所以只要包一层
> `requestAnimationFrame`、把时间戳换成指定值，就能把翻页**冻在任何一帧**。
> 这是做到「所有对照组停在完全相同的进度」的唯一可靠办法 ——
> 靠 `setTimeout` 猜时间在慢机器上必然对不齐。附带一条：`turnToPage()` 不走带动画的路径，
> 读不到进度，要量进度必须点按钮或拖拽。

## ★ 输入框和服务端：谁说了算（踩过坑）

工作台的原则是「排版方案的唯一事实来源在服务端」，但**书名/副标题这两栏是例外**：
一旦你在这两栏敲过键盘，这一栏就归你所有，服务端的回包不再往回写。

不这么做会怎样：服务端把空书名兜底成默认书名
（`serve_ui.py`：`SESSION.title = title.strip() or core.DEFAULT_TITLE`），
删掉最后一个字的 420ms 后回包一到，`renderStatus()` 就把兜底值写回输入框 ——
表现就是**「永远删不掉最后一个字，原文字自己回来了」**；
而且改版式、拖序触发的任何一次重渲染都会再顶一次。

现在的规矩（`ui/app.js` 的 `syncField()`）：

| 情况 | 输入框 |
|---|---|
| 用户在这栏敲过键盘（`drafts.title !== null`） | **一个字都不动**，包括他自己删成空串 |
| 光标正停在这栏 | 不动 |
| 以上都不是 | 跟随服务端（首屏加载、换照片目录走这条） |

留空时输入框下面会出现一行小字「书名留空时用默认「我的小狗」」——
**兜底逻辑一个字没改**，只是把这件事说清楚，否则用户会以为「我明明删了，为什么书里还有字」。

`verify_ui.mjs` 用四条断言守住它（`成功4b`~`成功4e`）：删干净后 1.4s 内值不许变、
服务端仍按默认书名、**改版式触发的重渲染也不许顶回**、提示小字要在。
判据只看行为：用户最后一次按键之后没有再输入，输入框的值就不许再变。

> 写这几条断言的坑：第 4d 条**不能点后面第 5 步要用的那张卡片** ——
> 点同一张会「取消选中」，把 `#selected-box` 的等待直接等空，验收会挂在毫不相干的地方。

### 顺带：界面代码不许被浏览器缓存

`serve_ui.py` 原来对所有静态资源统一 `max-age=3600`。改了 `app.js` / `style.css`
之后刷新还是旧副本，现象就是**「改动没生效」**，排查方向会被带偏（这一轮真被它骗过）。

现在 `.html` / `.js` / `.css` 一律 `no-store`，字体与图片继续缓存（体积大、极少改）。
`verify_ui.mjs` 的 `成功7` 直接读响应头守住这条。

## ★ 书压住底部按钮 + 后壳翻不动（Phase 27，两个各自独立的坑）

佘先生：「要求一是修复查看画册时的选择页数的UI组块和图片有重合冲突，
要求二是画册的后壳也要可以翻页合上」。

### 一、书压住底部按钮：一个「估算」被后来的改动作废了

`.book-rig`（装书那个框）的宽高原来写死一件事：

```css
width:  min(100%, calc((100dvh - 140px) * var(--page-ratio) * 2), calc(640px * var(--page-ratio) * 2));
height: min(calc(100dvh - 140px), 640px);
```

那句 `140px` 的原注释是 `Reserve room for navigation` —— 一个**估算**。
当时脚部只有「页码 / 一行小字 / 自动翻页 / 调速」四行、高约 79px，够用。
Phase 26 往脚部加了第五行（常驻跳页控件）之后，脚部实测涨到 **121.2px**，就不够了。

真浏览器量出来的越界量（书底 − 控制条顶；负数才是让开了）：

| 窗口 | 修复前 | 修复后 |
|---|---|---|
| 1440×900 | −38px | −38px |
| 1280×800 | **+40px** | −16px |
| 1100×720 | **+60px**（正好压住跳页那行） | −16px |
| 1024×768 | **+51px** | −16px |
| 900×600 | **+60px**（同样压住） | −16px |
| 760×620 | **+42.5px** | −16px |

**修法：不再估，直接量。** 把 `.stage` 声明成**尺寸查询容器**，
`100cqh` 就是「这个席位里真正还剩多少高」：

```css
.stage    { container-type: size; }
.book-rig { width:  min(100%, calc(100cqh * var(--page-ratio) * 2), calc(640px * var(--page-ratio) * 2));
            height: min(100cqh, 640px); }
```

★ **宽和高压根都要改。** 只收高度是没用的：库是 `size: "stretch"`（按宽推高），
宽度照样把书撑高 —— 还是压。这一点单看"高度不够"是想不到的，是量出来才发现的。

★ 顺带记一笔口径：那个 `100cqh` 解析的是 `.stage` 的**内容盒**高度，
所以 `.stage` 自己那 `padding: 16px 0` 正好变成书与控制条之间那道 16px 的缝。

### 二、后壳翻不动：库自己两道守卫互相矛盾，而且异常被吞了

**症状**：走到最后那一跨页（版权页 + 封底）之后再点「→」，
**完全没反应**；而那个按钮**看起来还能点**（`disabled` 仍是 `false`）。

**根因在库建跨页表的算法里**（`PageCollection.createSpread`）：

```js
this.isShowCover && (this.pages[0].setDensity("hard"), this.landscapeSpread.push([t]), t++);
for (let e = t; e < this.pages.length; e += 2)
  e < this.pages.length - 1 ? this.landscapeSpread.push([e, e + 1])
                            : (this.landscapeSpread.push([e]), this.pages[e].setDensity("hard"));
```

开了 `showCover` 时它先把第 0 页单列（下标从 **1** 起），然后从 1 起、**步长 2** 两两成对；
只有在轮到的下标恰好等于 `总页数 - 1` 时，才把末页单独列出来。
⇒ **总页数为奇数时，末页永远被配进上一对里，"只含末页"的跨页根本不存在。**
我们的书是 `封面 + N 张照片 + 版权页 + 封底 = N + 3`，
N 为偶数（比如 100）时正是**奇数页**，所以永远到不了那个状态。

**更难受的是库自己的守卫打架**：

```js
checkDirection(t) { return 0 === t ? this.app.getCurrentPageIndex() < this.app.getPageCount() - 1
                                   : this.app.getCurrentPageIndex() >= 1; }
flipNext(t) { this.flip({ x: ..., y: ... }); }   // flip() → start()
// start() 里： this.flippingPage = getFlippingPage(s);   ← 取 跨页表[当前+1]
```

`checkDirection(0)` 判 `101 < 102` 就**放行**，可紧接着 `getFlippingPage(0)` 去取
`跨页表[52]`（不存在）拿到 `undefined`，里层一读 `.length` 就抛错 ——
而那句 `try { ... } catch (t) { return false; }` **把异常整个吞掉**。
于是表现成「守卫说能翻、执行时静默失败」：点了没反应，控制台连个错都没有。

**修法：不动页数、不动版式、不动 `book-plan.json`，只补一个"只含末页"的跨页。**

库对单页跨页**本来就有完整支持** —— `showSpread()` 里专门有一支：

```js
"landscape" === this.render.getOrientation() && t[0] === this.pages.length - 1
  ? (this.render.setLeftPage(this.pages[t[0]]), this.render.setRightPage(null))
  : (this.render.setLeftPage(null), this.render.setRightPage(this.pages[t[0]]))
```

横屏时末页放**左页**、右页留空；配套的 CSS `.book[data-edge="back"]` 把整本书右移 25%，
正好把它居中。也就是说**「合上」这个状态库早就设计好了，只是奇数页数时到不了**。

补丁（`runtime/flipbook.js` 的 `ensureBackCoverSpread`）只在需要时补、而且幂等：

```js
const tail = spreads[spreads.length - 1];
if (tail && tail.length === 2 && tail[tail.length - 1] === lastIndex) spreads.push([lastIndex]);
```

**实测（1440×900，103 页《深圳》）**：

| | 补之前 | 补之后 |
|---|---|---|
| 点「→」后停在 | 跨页 51（纹丝不动） | 跨页 **52** |
| 可见页数 | 2 | **1**（只剩封底） |
| `data-edge` | `inside` | **`back`**（书右移居中） |
| 状态条 | `102 / 103` | **`Back cover`** |
| 「→」按钮 | `disabled=false`（能点却没反应） | 补丁当时改成 `disabled=true`；**Phase 28 之后不再变灰**（见下一节：到头再点它是"整本翻回封面"） |
| 点「←」 | — | 原样翻回跨页 51（**可逆**） |

⚠ 两点限制（都不是缺陷，是库的设计）：
1. **竖屏**本来就每页一个跨页，末页天然单独 —— 所以这个补丁只对横屏有意义，
   而竖屏的"合上"和"翻到最后一页"本来就是同一个样子。
2. **自动翻页**仍然停在末跨页（不替用户"合上书"）—— 那是原行为，没动。
   合上是一个**手动**动作。

## ★ 控制条压成两行 + 到头翻回封面（Phase 28）

佘先生：「要求一是，查看画册时的那个页数和自动翻页UI组块太大了，上下宽度压缩一半，
要让图片占据画面的绝大部分，比如那个自动翻页和其速度组块完全可以放在同一行，
跳转页面的组块做成一行，要求二是我翻到后壳后再点击两下就可以翻到封面，就是整本书翻转」。

### 一、控制条：五行 → 两行

原来是竖排**五行**、实测 **121.2px**：

```
状态（Cover / 102 / 103）
一行说明小字
跳到第 [__] 页 [跳转]
自动翻页
5 秒 ▾
```

现在**两行**，实测 **46.6px**（= 改前的 **38%**）：

```
第 1 行  [Cover] 跳到第 [__] 页 [跳转]        ← 页数这一件事在一行里
第 2 行  [自动翻页] [5 秒 ▾] 点击页码可跳转…   ← 他点名要同一行
```

| 窗口 | 控制条高 | 书高占视口 |
|---|---|---|
| 1440×900 | 46.6px | 71.1% |
| 1280×800 | 46.6px | 80.0% |
| 1100×720 | 46.6px | 80.4% |
| 1024×768 | 46.6px | 79.4% |
| 900×600 | 46.6px | 76.4% |
| 760×620 | 46.6px | 71.8% |

> 上表是 **Phase 28 当时**的读数。Phase 31 把页码放大（10px → 15px）并删掉说明小字后，
> 现在实测**控制条 49.6px、书占视口 71%~80%** —— 只高了一点点，书没有被挤小。
> 第 2 行末尾那句"点击页码可跳转…"**已经整段删掉**了。

三个容易踩的点：

1. **行数少一半，中缝那列就得放宽**（280 → 344px）。窄了会挤到换行，**反而更高**。
2. **那个"看着像一行文字"的页码按钮，`height` 得一并收回来。**
   `.controls button` 给的是 36px 见方（那是两侧圆形箭头要的）；页码按钮套上 36px，
   会在这个"两行"里留下 **16px 的隐形空白** —— 控制条白白高出 16px，而肉眼看不出是谁占的。
3. **说明小字是挪走、不是删掉**（挪进第 2 行末尾），≤700px 窗口里由 CSS 藏起来；
   不藏的话 420px 视口下第 2 行会横向溢出（那一列只剩约 236px）。

### 二、到头再点「→」= 整本翻回封面

Phase 27 补完那个"只含末页"的跨页之后，到末页点「→」就翻不动了（按钮还变灰）。
Phase 28 让它**再点一下把整本书翻过来、回到封面**：

```js
if (atFinalSpread()) { if (WRAP_TO_COVER) pageFlip.flip(0, "top"); return; }
```

★ 两个刻意的选择：

- **用 `flip(0, "top")` 而不是 `turnToPage(0)`。** 后者走的是 `showSpread()`，是
  **瞬间跳、没有翻页动画**；前者走 `FlipController.flipToPage()`，会真的演一次翻页 ——
  一本合上的书被整个翻过来，落到封面。这才是他说"就是整本书翻转"想要的那个观感。
- **自动翻页不走这条路。** `autoTick()` 在 `atLastSpread()` 就自停了，
  所以"放着不管"永远不会自己绕回封面（Phase 20 的原行为，一个字没动）。

★ **判"到头了没有"必须问库的跨页表**，有两个陷阱：

```js
// ✗ 错：横屏末跨页的 getCurrentPageIndex() 报的是**左页位** 101，总页数却是 103
currentPage >= pageFlip.getPageCount() - 1
// ✗ 也错：atLastSpread() 是给"自动翻页该停了"用的，它在**末跨页**就已经是 true
//   （getSpreadIndexByPage(末页) 返回的是那个跨页的序号，而末跨页里就有末页）
// ✓ 对：直接看当前那张跨页表里，是不是已经最后一格
collection.getSpread().length - 1 <= collection.getCurrentSpreadIndex()
```

`getSpread()` 会**按当前朝向**返回横屏那张表或竖屏那张表，所以横竖两套坐标都不用特判。

**实测（1440×900，103 页《深圳》）**：末跨页 51 →①点「→」跨页 52（只剩封底、`edge=back`、
`Back cover`）→②再点「→」**跨页 0**（只剩封面 `[封面]`、`edge=front`、状态 `Cover`）。

## ★ 封面引入外部字体（Phase 30）

在「编辑封面文案」里可以直接导入自己电脑上的字体文件（`.ttf / .otf / .woff / .woff2`）。

**字体存在哪**：`photo-flipbook-tool\user-fonts\`（工具自带的字体库）

```
user-fonts\
├── fonts\          字体文件本身（按 key 命名）
└── registry.json   登记簿：key / 显示名 / 文件名 / 格式 / 来源 / 授权说明
```

**链路**（预览和出书走同一套，所以不会出现"预览好看、出书变了"）：

1. 界面下拉选「＋ 从电脑里选字体…」→ 选文件 → 上传
2. 服务端**只看文件头 4 个字节**认格式（`\x00\x01\x00\x00`/`true`=TrueType、`OTTO`=OpenType、
   `wOFF`=woff、`wOF2`=woff2）—— 不装任何第三方库，也不信文件扩展名；
   认不出来就**拒绝并提示**，不会把一张图当成字体收进来
3. 收进 `user-fonts\` 并写进登记簿（重名自动加序号）
4. 预览与出书都从登记簿取，**只有登记过的字体才认**（白名单）
5. 出书时：**这本书用到了才拷进书里**，并生成 `style/user-fonts.css`；
   没用到的字体不进书 ⇒ **老书一个字节都不会变**

**顺手修掉的一个真 bug（长期潜伏，Phase 30 才发现）**：
封面调过的**字体 / 位置 / 字号 / 颜色**在**成品里从来没有生效过** ——
翻页库初始化时会整体重写每一页的 `style` 属性（写定位与尺寸），
把服务端写进去的 `--ct-*` 变量一并冲掉了；而预览页没有翻页库，所以预览看着一直是好的。
修法：同一份值在 `<head>` 的内联样式里**再落一份**（库不碰那里），
选择器 `.art-page[aria-label="封面"]`。

**怎么防止它被改回去**

| 层 | 守什么 |
|---|---|
| 核心 `成功X` | 零依赖识别 + 白名单只认登记的 + 用到才拷进书 + 没用到时 head 一字不多 + **封面变量在 head 里另有一份**。带**五处负向自证**。 |
| 成品 | 真浏览器量：`document.fonts.check` 通过、computed font-family 真是那个字体、**用 Range 量标题"文字本身"的宽度**（量盒子量不出差异 —— 标题是绝对定位块，宽度由 left/right 撑满，与字宽无关）、控制台无错。 |
| 重出对账 | `_p30_rebuild_sz.py`：默认态的书重出后，`index.html` **剥注释逐字节相同**。 |

> ⚠ **字体授权**：自带字体（Source Serif 4）是 SIL OFL，可商用。

### ★ 顺手抓出并修掉的一个真 bug：松手中键会倒退一页

所以"在书元素上拦中键"根本拦不住它 —— 库照样当"用户开始拖拽"，
松手时走 `userStop()` 的 `flip(p)` 分支（＝"在左半页点了一下"）⇒ 自己翻回上一页。

修法：在**捕获阶段**（比翻页库、比书上任何监听器都早）把 `mousedown` / `mouseup` 的
中键（`button === 1`）拦掉并 `stopImmediatePropagation()`，让库根本看不到中键。
只拦中键 —— 左键拖拽翻页、左键双击翻整本，一个字没动。

## ★ 滚轮改缩放 · 中键什么都不做 · 放大要铺满整屏（Phase 32）

原话：

> 「我在阅读画册时的操作很不方便，优化一是鼠标中键滑动改成缩放功能，摁住鼠标中键暂时不要有什么操作，
> 优化二是图片放大时要全屏显示，注意不是窗口大小不变而图片只放大一部分」

### 一、滚轮：从「翻页」改成「缩放」

| | 改前（Phase 29 起） | 改后（Phase 32） |
|---|---|---|
| 单独滚滚轮 | 翻页（上=左翻 / 下=右翻） | **缩放照片**（上=放大 / 下=缩小） |
| 按住中键 | 按住中键 + 滚滚轮 = 缩放 | **什么都不做**（不翻页、不缩放、不拖拽） |
| 要不要按键 | 要按住中键才缩放 | **不用按**，滚就是缩放 |

**翻页还有别的入口，一个都没少**：左右方向键、两边的圆形箭头按钮、点书页、拖拽、点页码跳转、自动翻页。
撤掉的只有"滚轮"这一条 —— 这是**他本人说的「改成」**，不是我们私自砍功能。

### 二、放大要铺满整屏（不是"在原来那一小块里放大"）

这里有个**歧义，当场问了他**：「全屏」可以指 ① 一滚就铺满，也可以指 ② 逐步放大、滚到位才铺满。
**他选了 ②**。所以手感是：

| 滚到第几格 | 倍率 | 照片 |

| 1~6 格 | 1.00 → 2.81 | 平滑长大，**鼠标指着哪一点，那一点就不动** |
| 第 7 格 | ≈2.81 倍起 | 横向刚好铺满整屏，开始**钉住边**（此后瞄点让位，这是"要铺满"的代价） |
| 到顶 | **4 倍**封顶 | 照片**盖满整屏**，横向纵向都超出画面 |

### ★ 两个真踩到、而且三层全绿也盖不住的坑

**坑一：照片被隔壁那一页整块盖住**（右半屏永远是邻页原尺寸）
根因是翻页库每帧都执行 `element.style.cssText = "…; z-index: 11"` ——
**内联样式压过任何普通选择器**，所以我写的 `.book-page.zoomed { z-index: 40 }` computed 实测**还是 11**，
整段被吃掉。而且在**页内部抬 z 一律无效**（`.plate` / `img` 怎么加都没用），因为
`.stf__block` 不新建层叠上下文、104 个页元素是**同一层的兄弟**，**同跨页左右两页永远同 z**。
⇒ 只能从页元素这一层解决，且**必须带 `!important`**：`.book-page.zoomed { overflow: visible !important; z-index: 50 !important }`。

**坑二：第一格瞄点就跳 60px**（鼠标底下的照片点从 387.00 跳到 327.97）
两个错误叠在一起：
- `transform: translate(X, Y) scale(s)` 里的 `X` 是**照片左上角在舞台坐标系里的位置**（含 1 倍的落位），
  而 `translate` 的位移是**相对自身布局位置**的 ⇒ 必须写 `nx − o.x, ny − o.y`；
- "铺满才夹紧"的上界一开始写成 `Math.min(0, …)`（等于假设 1 倍就已铺满），
  实际 1 倍照片只有 512×640、要 **2.8125 倍**才横向铺满 ⇒ 第一格就把左上角从 (208,105) 钉到 (0,0)。
⇒ 修法：分轴算 `sCoverX = 宽/照片宽`、`sCoverY = 高/照片高`，**各自够长了才夹各自那一边**
（用 `max` 一起判会"纵向白夹"、照片凭空上移）。
修后前 6 格瞄点漂移 **0.000 照片像素**。

### 三、顺带把画面让给照片

底部控制条之外的空间全部还给书：`.room` 改成整屏（`height: 100dvh; padding: 0`），
标题栏改成浮在画面上方（不再占一行），舞台只留 4px 边距。

## ★ 双击改成「逐页急翻 5 下 + 瞬间切到另一头」（Phase 36）

⚠ **本节取代上面 Phase 34 / Phase 35 里关于「整叠块面翻页」的全部做法** ——
那两节留着是为了记录"为什么当初那么做、又为什么被否"，**代码层面的东西已经整套退役**
（`startSlabFlip` / `slabJumpToEnd` / `SLAB_*` / `COVER_NORMAL_*` / `.stack-flip` /
`.stack-mask` 全部删除，判据里列为**禁出现**）。

你 2026-09-28 看完成品后说的话：

> 「鼠标左键双击的块面翻页效果**很不好看**，你有什么好的方案呢」
> （追问"难看在哪"）「**一整块转半圈太机械**」
> （问怎么办）「**逐页急翻五面，然后就不翻了，直接跳到封面和后壳，在后壳处翻转也是一样的**」

### 一、现在的效果

| 操作 | 结果 |
|---|---|
| 在**封面上**连击鼠标左键两次 | **一页页急翻 5 下**（每下约 0.26 秒），翻完**瞬间切**到后壳（书合上，看到封底） |
| 在**后壳上**连击鼠标左键两次 | 同样**急翻 5 下**，然后**瞬间切**回封面 |

- **"5 下"是数出来的**：一下 = 库的一个 `flip` 事件。真双击本身只派发 **1 个** `flip`
  （第二下在翻页动画途中被库吞掉），所以程序把这一下**从总数里扣掉**，再自己补 4 下 ——
  加一起正好 5 下（不是写死的"补 4 下"，是 `需要 = 5 − 已经翻的`）。
- 急翻期间**点箭头 / 按方向键能立刻叫停**（那一趟马上收掉，第二次点就正常翻页）。
- 翻完那一下是**瞬间切换**、**没有任何淡出滑过** —— 你要的就是"直接跳"。
- **急翻把翻页动画临时提速**（0.76 秒 → 0.26 秒），**翻完自动还原**；
  之后你自己点箭头，速度跟平常一模一样。

### 二、为什么"5 下"必须数事件、不能换算页数

实测（`_p36_probe0.mjs`）：

- 真双击封面只派发 **1 个** `flip`（页位 0→1）；第二次单击在动画途中被库吞了。
- 而单次 `flipNext("top")` 的页位增量是"封面那下 **+1**、之后每下 **+2**"。

两者不成线性 ⇒ **页位差 ≠ 翻了几下**。所以只能数 `flip` 事件，
再用"按下鼠标那一刻的快照"把双击自带的那下扣掉（findings 105）。

### 三、顺手修掉一个真 bug

急翻那一趟每一下都占着"正在翻页"这个状态（0.26 秒一下、间隙只有 0.05 秒），
而「点箭头」那个入口原本先判"是不是正在翻"、再停自动/急翻 ——
于是那 1.5 秒里**点箭头完全没反应**，跟卡住一样。

## ★ 看画册时能进「真全屏」——浏览器标签页都收走（Phase 39）

佘先生：「我想可以不可以真正的全屏，就是说浏览器没有标签页」。他选的是
**「按一下才进」**（不是打开就无标签页）⇒ 控制条第 2 行上一颗 **「全屏」** 按钮。

- 用的是 **Fullscreen API**（`document.documentElement.requestFullscreen({ navigationUI: "hide" })`）。
  这是唯一能真把**标签页 / 地址栏 / 系统任务栏**一起收走的做法；单把页面 CSS 拉大，
  永远留着浏览器的壳。
- 出口三条，都是浏览器自己给的：**再点一下那颗按钮、按 `Esc`、按 `F11`**。
  三条都走 `fullscreenchange` ⇒ 按钮文案永远跟真实状态一致，不会"看着没进全屏"。
- ★ **按钮是 `flipbook.js` 现拼 DOM 插进 `.auto-row` 的，不写进 HTML。**
  成品 `index.html` 由 `make_flipbook.py` 的内嵌模板生成，改模板就得**重出书**；
  而 `flipbook.js` / `styles.css` 是逐字节拷贝的，所以这样改完**同步一下就行**
  （和灯箱、急翻同一个套路）。老成品 HTML（没有 `.auto-row`）会安静地不加按钮，其余一字不动。
- 样式 `.status .page-full` 与旁边的 `#page-auto` **同一副药丸长相**（9px 字、999px 圆角、
  同一个边框色）；进全屏后整体反色。实测它与邻居**同高同轴**（都 18.6px、中心线差 **0px**），
  所以**控制条一点没被撑高**（仍 49.6px，判据上限 61px）。

### 验收怎么量（无头浏览器的两个坑）

- 无头 Chromium **支持** `requestFullscreen`（`fullscreenElement` 有值、`:fullscreen` 命中），
  这条可以放心写成常驻判据。
- ⚠ **但无头里按 `Esc` 退全屏不生效** ⇒ 退全屏只量「再点一下那颗按钮」，
  另加一条 `document.exitFullscreen()`（真浏览器里按 `Esc` 走的就是它），
  **绝不量 `Esc` 按键本身** —— 量了是假红，会误判成产品 bug（findings 117）。
- ⚠ 进全屏那条必须先断言「量之前本来不在全屏」，否则后面的断言全都建立在假前提上。
- ★ 同步改动时要覆盖**画册集里的每一本**，不能只改一本：验收对象是按
  `book-plan.json` 的 `generated_at` 挑**最新那本**的（这次挑中的是《我的小狗》，不是《深圳》）。

## ★ 点「打开画册」= 无边框全屏（Phase 40）

佘先生 2026-09-30：「我想要的全屏是类似电脑游戏的全屏模式」「**是屏幕上方不能有
浏览器显示**」。他定的做法：**工作台那颗「打开画册」直接以无边框全屏打开**。

### 一、做法：命令行开，不问浏览器

```
<browser>.exe  --app=file:///…/index.html  --start-fullscreen
```

- `--app=` 是 Chromium 的「应用窗口」：**没有标签页、没有地址栏**。
- 叠上 `--start-fullscreen` ⇒ 顶满整屏，屏幕最上方就是画册本身。
- 这条路**不经过任何权限**（不像网页申请 Fullscreen API 要看浏览器脸色），
  2026-09-30 已在他屏幕上**抓真实像素**确认过。

### 二、为什么不能靠网页里那颗「全屏」按钮顶替

★★★ **「浏览器壳收没收走」这件事，自动化根本验不了**（findings 119）：
实测 Playwright `launch()` 与 `connectOverCDP`（真 Chrome 153 与 Tabbit 都试过）
点出来的全屏，`document.fullscreenElement` 有值，但 **`innerHeight` 一点都不变、
整屏真实像素两张图 md5 完全相同** —— 自动化下 Chromium 只改内部状态，
**不做 OS 级窗口转换**。所以 Phase 39 那 9 条判据只能证明「按钮调到了 API」。

### 三、★ 认亲：`--app=` 只有 Chromium 系认

认不出来的时候，别的浏览器**不报错**，只是把 `--app=` 当垃圾参数丢掉，然后开出一个
**带标签页的普通窗口** —— 要求落空还看不出来。所以 `ui_common.open_book_fullscreen()`
先认亲：看 exe 旁边（含版本子目录）有没有 `chrome.dll` / `msedge.dll` /
`chrome_proxy.exe` / `msedge_proxy.exe` / `chrome_pwa_launcher.exe` / `resources.pak`。
**看家当、不看名字** —— 本机默认那个套壳 Chromium 就叫 `Tabbit Browser.exe`。

三种认不出的情况**一律退回老办法**（系统默认浏览器按普通标签页打开），
绝不「点了没反应」：

| 情况 | 结果 |
|---|---|
| 不是 Windows / 读不到 `UserChoice` | 退回 `open_in_browser` |
| 抠不出 exe，或它不像 Chromium | 退回 `open_in_browser` |
| 命令发出去了但启动失败 | 退回 `open_in_browser` |

（`selftest.py` 的「成功AC」把这三条负向都钉住了，而且**一条浏览器都不启动**：
把 `_run_detached` 换成记录器，只看「该发什么命令」。）

### 四、⚠ 两个已知代价

- **`Esc` 退不出来**：`--start-fullscreen` 是浏览器级全屏（F11 那种），
  退出要按 **`F11`**。工作台那颗按钮的 `title` 里写了这句。
- **本机默认浏览器是 Tabbit Browser**（`TbBrHTM.*`，Chromium 152 套壳），
  不是 Chrome/Edge —— 见 findings 121。**双击 `index.html` 那条路没改**，
  还是普通标签页打开。

## ★ 写 .bat 的两条硬规矩（踩过坑，别再犯）

**1. 行尾必须 CRLF，内容必须纯 ASCII。**

`cmd.exe` **解析不了只有 LF 行尾的批处理脚本** —— 它会把 `if` / `set` 链读错，
症状就是「黑窗停住并报错」。另外中文 Windows 控制台默认代码页是 936（GBK），
`.bat` 里写的 UTF-8 中文会被解成乱码，同样报错。

所以启动脚本一律用英文注释和英文提示，需要中文提示就交给 Python 去打印
（Python 里显式 `reconfigure(encoding="utf-8")`）。

**2. 用 `pythonw.exe` 启动就不该留黑窗。**

`start "" /b "%PYW%" app\serve_ui.py` 之后立刻 `exit /b 0`，控制台窗口随脚本一起消失。
但 `pythonw.exe` 下 **`sys.stdout` 和 `sys.stderr` 都是 `None`**，
任何 `print()` 都会抛 `AttributeError: 'NoneType' object has no attribute 'write'`
把进程打崩（表现为双击完全没反应）。
所以 `serve_ui.py` 和 `run.py` 开头都有 `_ensure_writable_streams()` 兜底。

> 两边互不干扰，根目录只留双击入口和说明。脚本内部用「工具根」这个常量去定位
> `runtime\` / `ui\` / `logs\`，所以以后**再挪目录也不会断**。

> 交付物不在工具目录里 —— 做好的画册在**工作区的 `画册集\`**。
> 早先工具目录里那份 `photo-flipbook-tool\画册\` 已废弃（那是历史遗留的旧位置），
> 现以 `画册集\` 为准。

> **验收会出一本书**，但它出到工具目录下的 `.verify-probe\ui-sandbox\`，
> 不会碰你的 `画册集\`。这个目录留着复用（覆盖写入，从不删除）。
> ⚠ 别把它和 `.verify-probe\gate-画册集\`（验收对象替身书架）混成一个目录 ——
> 界面层每轮新出的书会**顶掉**成品层的验收对象。

> 约定：`_xxx` 开头的文件是**一次性探针**（排查问题时临时写的，用完即删）。
> 要留下来的脚本一律不用下划线开头 —— 上面 `verify_*` 三个都是常驻的。

### 解释器从哪来

入口不写死路径，而是按这个顺序找，**每个候选都要能 `import PIL` 才采用**：

1. 工具自己携带的 `python\python.exe` / `runtime\python\python.exe`（便携版，换机器也不怕）
2. `%LOCALAPPDATA%\Programs\Python\Python3*\python.exe`、`%ProgramFiles%\Python3*\python.exe`
3. `py` 启动器、PATH 上的 `python`

所以把整个工具文件夹拷到别的电脑，只要那台机器装了带 Pillow 的 Python 就能直接跑。

## 工作台为什么这么做

三件刻意为之的事，都是为了避开这台机器上的坑：

1. **服务只绑 `127.0.0.1`** —— 局域网里别人访问不到你的照片。
2. **服务端所有出站请求显式绕过系统代理** —— 本机常驻 `HTTP_PROXY`，不绕过的话连自己都连不上，回环地址会直接失败。
3. **界面不引用任何 CDN** —— 字体、材质、脚本全部本地提供。否则代理一抖动，页面就白屏。

另外，生成画册时**不删除上次的产物**，直接覆盖同名文件。结果与「先清空再生成」完全一致，但避免了大量删除动作——这台机器上的批量删除保护会按次数拦截，删多了会直接把进程打死。

关服务不靠端口也不靠进程名，而是读 `logs\.serve_ui.pid` —— 那是服务自己启动时写进去的 PID，所以永远只关掉这一个进程，不会误伤浏览器或别的程序。同理，**双击第二次时也靠它认出「这个端口上的是自己人」**（另外还要 `/api/status` 回一句 `app` 标记，确认不是别的程序碰巧占着 `8770`）。

## ★ 自动挑端口的坑：Windows 上 `SO_REUSEADDR` 会「抢」别人占着的端口

**症状**：`画册.bat` 的自动挑端口形同虚设。已经有一个工作台开在 `8770` 时，
再双击一次，第二个服务**照样绑上 8770**，两个服务挤在同一端口上。
`logs\.serve_ui.pid` 被后起的那个覆盖，于是只关得掉一个，
另一个变成谁也找不到的**僵尸服务**，端口一直被占着。

> **入口合并成一个之后，这个坑有了第二道防线**：`serve_ui.py` 启动时会先探一圈
> 「有没有本工具的工作台在跑」，有就直接开它的页面、根本不起第二个服务。
> 探活靠 `connect` + `/api/status` 的 `app` 标记（必须确认是本工具，
> 不然会把别的程序当成自己的工作台）。`--port` / `--output` 被显式指定时跳过复用 ——
> 那是验收脚本要起独立实例。所以上面这条回归断言仍然要守着，它管的是「确实要起服务时」。

**根因**：`find_free_port()` 原来是这样判断"这个端口空着"的：

```python
s.setsockopt(socket.SOL_SOCKET, socket.SO_REUSEADDR, 1)   # ← 问题在这
s.bind(("127.0.0.1", port))        # bind 成功就认为端口空闲
```

**Windows 上 `SO_REUSEADDR` 的语义等于 Unix 的 `SO_REUSEPORT`** ——
它明确允许把套接字绑到一个**别人已经绑着**的端口上，而且 `bind` 会返回成功。
（`ThreadingHTTPServer` 默认又是 `allow_reuse_address = True`，两边一起放行。）
所以那个循环第一次就 "成功"，直接返回了被占用的 8770。

**修法**：先 `connect` 探活（有人应答 = 被占），再用 `SO_EXCLUSIVEADDRUSE` 兜一次
（Windows 专有，保证别人占着就一定绑不上）：

```python
with socket.socket() as s:
    s.settimeout(0.35)
    if s.connect_ex(("127.0.0.1", port)) == 0:
        return True                      # 有人应答 → 跳过这个端口
with socket.socket() as s:
    if hasattr(socket, "SO_EXCLUSIVEADDRUSE"):
        s.setsockopt(socket.SOL_SOCKET, socket.SO_EXCLUSIVEADDRUSE, 1)
    try: s.bind(("127.0.0.1", port))
    except OSError: return True
```

`verify_shortcut.py` 里加了一条**回归断言**守住它：
开跑前先扫一遍 `8770~8820`，记下已占用的端口，然后断言「服务实际选中的端口不在其中」。
实测（本机 8770 上真留着一个没关的工作台）：服务自动选了 **8771**，断言通过。

> 顺带一条运维事项：这些**自动挑端口 + PID 文件**的设计决定了「机器上只能有一个工作台」。
> 测试期间就撞到过：`8770` 上挂着一个早先启动、一直没关的 `pythonw.exe`（属于工作台服务）。
> 判断办法：`netstat -ano -p TCP` 找到监听 `:8770` 的 PID → `tasklist` 看进程名。
> 想清掉就打开工作台点右上角「关闭工具」，或按 PID 结束它。
